## Usage

```tsx
import { ToolRenderer } from "@/components/commandly/tool-renderer";
```

### Basic Usage

```tsx
const [values, setValues] = useState<Record<string, ParameterValue>>({})

<ToolRenderer
  tool={tool}
  parameterValues={values}
  updateParameterValue={(key, val) =>
    setValues((prev) => ({ ...prev, [key]: val }))
  }
/>
```

### With a Specific Command

```tsx
<ToolRenderer
  tool={tool}
  selectedCommand={tool.commands[0]}
  parameterValues={values}
  updateParameterValue={(key, val) => setValues((prev) => ({ ...prev, [key]: val }))}
/>
```

### Custom Parameter Renderers

You can override how specific parameters are rendered by providing a custom `catalog`:

```tsx
import { defaultComponents } from "@/components/commandly/tool-renderer"
import type { ParameterRendererEntry } from "@/components/commandly/types/renderer"

const customCatalog: ParameterRendererEntry[] = [
  {
    condition: (p) => p.dataType === "String" && p.displayName === "format",
    component: ({ parameter, value, onUpdate }) => (
      <select value={String(value)} onChange={(e) => onUpdate(e.target.value)}>
        <option value="json">JSON</option>
        <option value="csv">CSV</option>
      </select>
    ),
  },
  ...defaultComponents(),
]

<ToolRenderer tool={tool} parameterValues={values} updateParameterValue={...} catalog={customCatalog} />
```

## API Reference

### ToolRenderer

| Prop                   | Type                                           | Default               | Description                                                                 |
| ---------------------- | ---------------------------------------------- | --------------------- | --------------------------------------------------------------------------- |
| `tool`                 | `Tool`                                         | -                     | The tool definition to render inputs for                                    |
| `selectedCommand`      | `Command \| null`                              | Auto-detected default | The command whose parameters should be shown; `null` renders the tool's own |
| `parameterValues`      | `Record<string, ParameterValue>`               | -                     | Current values keyed by parameter key                                       |
| `updateParameterValue` | `(key: string, value: ParameterValue) => void` | -                     | Callback to update a parameter's value                                      |
| `catalog`              | `ParameterRendererEntry[]`                     | `defaultComponents()` | Ordered list of renderer entries; first matching condition wins             |

### ParameterRendererEntry

| Field       | Type                                                        | Description                                     |
| ----------- | ----------------------------------------------------------- | ----------------------------------------------- |
| `condition` | `(parameter: Parameter) => boolean`                         | Predicate to match a parameter to this renderer |
| `component` | `(context: ParameterRenderContext) => ReactElement \| null` | Component that renders the input                |

### ParameterRenderContext

| Field        | Type                              | Description                                                                |
| ------------ | --------------------------------- | -------------------------------------------------------------------------- |
| `parameter`  | `Parameter`                       | The parameter definition                                                   |
| `flags`      | `string[]`                        | The parameter's invocation forms: the canonical flag plus its aliases      |
| `value`      | `ParameterValue`                  | The current value                                                          |
| `onUpdate`   | `(value: ParameterValue) => void` | Callback to push a new value                                               |
| `isRequired` | `boolean`                         | Whether the parameter must be provided, counting a `required_one_of` group |
| `excludedBy` | `string`                          | The exclusion group ruling the parameter out, once another member is set   |

## Notes

- The default catalog renders `Flag` → checkbox, `Option` → text/number/select input, `Argument` → text input
- Inherited parameters (`recursive: true`) are shown alongside the selected command's own parameters
- If `selectedCommand` is omitted, the component first looks for a command whose `displayName` matches `tool.binaryName`, then falls back to the first command
- A tool's own flags belong in `tool.parameters`, not on a command named after the binary, which would describe the root invocation twice
- Mutual exclusion is enforced: once one member of a `mutual_exclusive` group is set, the others are disabled and carry an `excluded by <group>` badge, and the generated command never emits two of them
- A custom renderer is given `excludedBy` and `isRequired`, so it can disable its own input the same way
- If `selectedCommand` is explicitly `null`, the component renders the tool's own parameters
- Provide a custom `catalog` to render domain-specific parameter types differently
